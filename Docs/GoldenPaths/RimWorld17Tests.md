# Waterworks 1.7 test-only golden path

## RimWorld 1.7 unstable test-only entry

Use `powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/Run-17Tests.ps1 -GameRoot "D:\SteamLibrary\steamapps\common\RimWorld"` **only** for a local 1.7 unstable installation with a separately built, inspected Waterworks production DLL already present. The 1.6 `Scripts/run-e2e.ps1` gate is unchanged. This runner does not compile, replace or modify production DLL or public About.xml.

The runner uses actual `Version.txt`, `RimWorld.exe`, current game DLLs and installed Pickle/Quickstarts, compiling only the existing two test assemblies with the Roslyn test helper. It stages one explicitly marked test-only companion Mod, runs the unchanged eight `waterworks-core.feature` scenarios on a hidden desktop with real rendering, checks the game-native log PID and ERROR=0, checks exact scenario names and counts, preserves normal ModsConfig/Prefs and production DLL hashes, and removes only its own marked fixture. Results are retained under `TestResults/RimWorld17-*/` per run.

**8 required scenarios and assumptions:** loaded canal Defs; four-direction connectivity; one-cell width; nine-cell natural freshwater source; Mud/Marsh excavation without false source; Vanilla bridge flow and ground restore; real pawn dig/fill jobs; save/reload restoration. These do not establish the separate add-to-existing-save 1+1 test, seven visual acceptance criteria, DBH integration or Workshop release. A 1.7 build/test failure is a finding, never a PASS. Native 1.7.4976 rev1043 execution passed on 2026-10-13; see the bounded [DBH/core test evidence](../Validation/DBHCanalCompatibility-20261013.md).

The local startup uncovered two real tooling defects: Windows PowerShell read the bilingual UTF-8 About.xml as ANSI, and the old Pickle driver exposed a UnityEngine.CoreModule MonoBehaviour reference to Roslyn. The runner now reads UTF-8 explicitly; the shared GameThread calls the exact `Post(Action)` dispatcher by reflection and still asserts `UnityData.IsInMainThread`. The 1.7 core/integration test build selects only its four owning step files, avoiding unrelated legacy Mesh-returning visual probes. This preserves every core assertion; it is not a replacement visual test or a production C#/.NET modernization.

`-Profile Solo|DBHOnly|Medieval`, `-Suite Core|Integration`, `-NeedsDisabled` and `-LiteMode` select isolated acceptance profiles. Integration requires Medieval and water management enabled; Lite runs core and asserts the partner canal/sluice Defs are absent. Installed partner DLLs still advertise 1.6 only: do not alter their metadata or claim upstream 1.7 support from these runs. Provider paths follow LoadFolders, including the existing Pickle/RimTest 1.6 fallback. CCTO and Environment's runtime helper was inspected and remains unchanged; Waterworks adds its own scoped dispatcher fix without making either Mod a dependency.
